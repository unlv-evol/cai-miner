This record accompanies the dataset and exploratory analysis reported in the paper "GHAgentCI: A Dataset of Coding-Agent Invocations in CI Workflow Histories" (MSR 2027 Data and Tool Showcase Track).

GHAgentCI holds the complete histories of 15,928 GitHub Actions workflow files that invoke a coding agent (Claude Code, Copilot, Codex, Gemini, Cursor, Aider and others), mined from 6,345 of 196,253 active GitHub repositories, with 205,832 agent invocations located at the job and step that make them. Agentic files are kept with their whole history, including the revisions before the agent was introduced and after it was removed, and every mined repository keeps a row, so adoption and abandonment can both be measured.

The dataset was created as follows:

  1. We queried GitHub SEART on 3 October 2026 for non-fork repositories with at least 300 commits, and kept those whose last commit falls within the preceding year (196,938 repositories). Repositories created at least a year before the query, the remaining sampling criterion of GHAgentFiles, are flagged with ghagentfiles_comparable, so results can be restricted to that population.
  2. We cloned each repository between 3 and 5 October 2026 as a partial clone without blobs above 64 KB, and applied the tool cai-miner (available on GitHub and PyPI, version 0.1.0) with its frozen detector catalogue. It walks the first-parent history of every file under .github/workflows/, parses each revision, and matches each step against the catalogue. Evidence is tiered: a dedicated agent action (uses), an agent CLI call (run), a reserved file name (path) and a GitHub Agentic Workflows header (ghaw) are strong; a reserved job id, an LLM endpoint or a bound credential are weak.
  3. Repositories that failed in the main pass were retried with a one-hour budget. The 681 that still failed, mostly deleted or made private since the query, keep a row with their failure as status.
  4. We kept what the paper counts: a revision is agentic with strong evidence for a named agent, and nothing before 30 November 2022 (the release of ChatGPT) counts. Author and committer emails are replaced by a salted SHA-256, so the same address is linked across the dataset without being disclosed; names are kept as git records them.
  5. Precision and recall were validated on stratified samples labelled independently by two coders; the samples, labels and adjudication are in the replication package.

The following files are provided:

  1. repositories.csv.gz: one row per repository of the sampling frame, agentic or not, including failed ones, with workflow counts, detected agents and a completeness check (n_blobs_missing).
  2. revisions.csv.gz: one row per change to a workflow file whose history is agentic at some point (git metadata, change type, parse status, triggers, permissions, detected agents).
  3. steps.csv.gz: one row per agent invocation (agent, evidence kind, matched pattern, job and step, action and version, triggers, purpose labels).
  4. ghaw_manifests.csv.gz: one row per revision of a GitHub Agentic Workflows source or compiled file (engine and version, compiler version, tool grants, MCP tools, permitted outputs, secrets, network policy, sandboxing).
  5. content.tar.gz: the content of every distinct workflow revision in the dataset, stored as content/<content_sha256>.yml.
  6. frame-2026-10-03.csv.gz: the sampling frame, with the SEART metadata used for sampling and the ghagentfiles_comparable flag.
  7. replication.tar.gz: the replication package: cai-miner at the version that produced the data, the raw SEART export, the mining run logs, the scripts that build the frame, the release and the paper's numbers and figures, and the validation material. REPLICATION.md inside explains how to regenerate the paper's statistics from the released tables, or re-mine from scratch.
  8. README.md: documentation of every column of every table.
  9. SHA256SUMS: checksums of all files.

The tables join on repository, on (repository, uid) for a file history, and on (repository, uid, commit_hash) for a revision; content_sha256 joins a revision to its content. The main columns are:

  1. repository: the repository (owner and name, separated by "/").
  2. uid: identifier of a logical workflow file, stable across modifications and renames. A file deleted and later recreated at the same path receives a new one.
  3. commit_hash, author_name, author_email, committer_name, committer_email, authored_date, commit_date: git metadata of the revision (emails hashed).
  4. file_path, previous_file_path, file_hash, previous_file_hash: path and git blob id after and before the commit; file_hash is empty for a deletion.
  5. git_change_type: Added, Modified, Deleted or Renamed.
  6. parse_ok: whether the revision is valid YAML; otherwise detection used a text scan.
  7. agent: the agent group (e.g., claude, copilot, codex); for GitHub Agentic Workflows, the declared engine.
  8. evidence_kind: the deciding evidence (ghaw, uses, run, path, job, url or env).
  9. scope, job_id, step_index, step_name: where the invocation is; scope is file when the evidence concerns the whole workflow.
  10. action, action_version: for uses evidence, the action and its reference (tag, branch or commit SHA).
  11. triggers, tasks: the workflow's events, and heuristic purpose labels (review, triage, implement, test, docs, security, scheduled, on_demand).
  12. actor_gated: heuristic flag, whether the workflow conditions on the triggering actor (e.g., github.actor).

List-valued columns are |-separated. Dates are ISO 8601 with the committer's own UTC offset; compare them as instants, not as strings. The full schema is in README.md. Downloads can be checked against SHA256SUMS.
