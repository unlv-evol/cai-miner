# Detector catalogue

Detection is driven by a TOML catalogue of agents and the patterns that
identify them. Three catalogues ship inside the package, in
`src/cai_miner/catalogues/`:

| file | what it is |
| ---- | ---------- |
| `catalogue.toml` | **the default.** The frozen catalogue GHAgentCI was mined with: `default.toml` and `marketplace.toml` merged. |
| `default.toml` | hand-written from vendor documentation: `run`, `url`, `env`, `path` and `job` patterns, plus the `[paths]`, `[tasks]` and `[exclude]` sections |
| `marketplace.toml` | generated from the GitHub Marketplace `ai-assisted` category: the long tail of `uses` patterns |

Pass `-c my.toml` to use your own. From Python, the bundled files are under
`cai_miner.config.CATALOGUES`.

## Evidence kinds

| kind   | matches                                                 | strength |
| ------ | ------------------------------------------------------- | -------- |
| `uses` | a step's `uses:` names a dedicated agent action         | strong   |
| `run`  | a step's `run:` shell-invokes an agent CLI              | strong   |
| `path` | the workflow file has a reserved, agent-specific name   | strong   |
| `ghaw` | the file was generated by GitHub Agentic Workflows      | strong   |
| `job`  | a job carries a reserved, agent-specific id             | weak     |
| `url`  | a step talks to an LLM inference endpoint               | weak     |
| `env`  | an agent or LLM credential is bound at that scope       | weak     |

A revision is agentic only if it carries strong evidence, unless
`--include-weak` is given. `ghaw` needs no pattern: the gh-aw compiler
identifies its own output (see [GitHub Agentic Workflows](ghaw.md)).

Why a filename can be strong evidence: GitHub's Copilot coding agent is wired
in by reserved filename. GitHub reads `.github/workflows/copilot-setup-steps.yml`
and runs the job of the same name, and neither carries a `uses:` or `run:` that
names Copilot. The reserved *file* is the contract GitHub honours, whereas the
reserved *job id* in some other file is a copied template GitHub never reads,
so only the former is strong.

`env` evidence is attributed **once, at the scope that declares it**: a step's
own `env:` to that step, a job's to the job, the workflow's to the workflow.
Folding outer scopes into each step would claim `actions/checkout` is an agent
invocation because the workflow exports `ANTHROPIC_API_KEY` at the top.

## Matching

`uses` patterns match an action exactly: `owner/repo` matches `owner/repo@v1`
and `owner/repo/sub@v1`, but not `owner/repo-other` or `xowner/repo`. The other
kinds match as case-insensitive substrings.

## Format

```toml
# Which files are CI workflows at all.
[paths]
github_actions = [".github/workflows/*.yml", ".github/workflows/*.yaml"]

[agents.myagent]
display_name = "My Agent"
uses = ["myorg/my-agent-action"]
run  = ["myagent --run"]
env  = ["MYAGENT_API_KEY"]
url  = ["api.myagent.example"]
path = [".github/workflows/myagent-setup.yml"]
job  = ["myagent-setup"]
```

Extending detection needs no code changes. Copy `default.toml` as a starting
point; it also shows the `[tasks]` and `[exclude]` sections.

### Composing catalogues

A catalogue may `include` others, resolved relative to its own location:

```toml
include = ["default.toml", "marketplace.toml"]

# Rename an agent group from an included file.
[aliases]
qodo = "pr_agent"

# Move one `uses` pattern to a different group.
[overrides]
"codota/tabnine-pr-agent" = "generic_ai"
```

Patterns are unioned per agent group, and `[aliases]` and `[overrides]` apply
after merging. This is how `catalogue.toml` is built without editing either
source file, so the generated one can still be regenerated and diffed.

## The frozen dataset catalogue

`catalogue.toml`, `default.toml` and `marketplace.toml` are frozen at the
versions that produced GHAgentCI, and a test checks their SHA-256 sums. The
dataset's validation sample only holds for the patterns that produced the
data, so a change to detection belongs in a new catalogue file, not in these.

## Regenerating the Marketplace catalogue

`marketplace.toml` is produced by a script in the source repository (not part
of the installed package):

```bash
uv run python scripts/build_catalogue.py -o new-marketplace.toml
```

It enumerates the Marketplace `ai-assisted` category, resolves each listing to
its source repository, and groups repositories belonging to a known agent
vendor under that agent, with everything else under `generic_ai`. Vendor
grouping rules live in `_AGENT_RULES` in the script.
