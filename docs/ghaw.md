# GitHub Agentic Workflows (gh-aw)

`gh-aw` is GitHub's first-party agentic workflow framework. An agent is
authored as Markdown in `.github/workflows/` and compiled by `gh aw compile`
into an ordinary `.github/workflows/<name>.lock.yml`. Both halves are
committed, so both appear in history, and `cai-miner` collects both: only the
source carries the tool grants and output constraints, while only the compiled
file carries resolved versions, pinned action SHAs and container digests.

## Detection is exact

The compiler stamps a machine-readable header into every file it generates:

```
# gh-aw-metadata: {"schema_version":"v4","agent_id":"copilot", ...}
# gh-aw-manifest: {"secrets":[...],"actions":[...],"mcp_servers":[...]}
# This file was automatically generated by gh-aw. DO NOT EDIT.
```

The header layout has changed across compiler releases and every generation
appears in history, so all are parsed: v0.44 has only the generated-by marker,
v0.56 (schema `v2`) adds `gh-aw-metadata` after an ASCII-art banner, and by
schema `v4` the metadata and manifest are the first two lines.
`compiler_version` and `schema_version` are recorded per revision, which makes
the framework's own evolution observable.

This tier needs no catalogue and no evidence tiering: the framework identifies
itself. It also carries a much richer payload than "an agent is present here":
which agent and which version, the MCP tools it may call, the outputs it is
permitted to emit, its network egress policy and whether it runs sandboxed.
These land in [`ghaw_manifests.csv`](output.md#ghaw_manifestscsv-one-row-per-gh-aw-artifact-revision).
